# Phone Use 权限与连续性

控屏 → 权限 →「Phone Use 权限预设」提供三档，新任务读取所选预设，进行中的任务保持开始时配置。旧配置、缺失或无效值使用 Manual。

| 预设 | 普通敏感提交与系统授权 | 严重风险 |
| --- | --- | --- |
| Manual | 灵动岛逐次请求用户批准 | 人工批准 |
| Auto | 模型先审计具体动作；不确定、无效或审计失败转人工 | 人工批准 |
| YOLO | 自动同意 | 人工批准 |

常规打开应用、选择打开方式由模型按用户目标自主决定。小米安全中心普通页面可以读取；可读选择/授权弹窗也返回观察，不再仅因包名或启动中出现弹窗就终止。发起 launch 不代表已打开，必须以目标应用的新观察确认。

发送、发布、删除及一般权限属于敏感操作。实际付款/转账、账户安全变更、泄露凭证、关闭安全保护、永久授权等属于严重风险。模型需用 `requires_confirmation`、`risk_level` 和具体 `message` 标记；执行器另根据可读目标标签、已知授权包与标题识别部分风险。说明缺失时，确认卡附可读目标标签，不附输入内容。目标识别和已知模板不构成全应用风险识别保证。

原生 Auto 首次提交候选动作只产生随机审计挑战，不执行、不消耗动作预算。模型下一次需审计用户原始目标、动作对象、内容、范围及后果，原样提交候选动作并附 `permission_review={token,decision,reason}`。挑战内坐标已经归一化，续调必须显式使用 `coordinate_space=normalized`。审计决策为 `allow`、`ask_user` 或 `deny`；挑战绑定会话、具体动作、原观察及 60 秒期限，消费一次。`ask_user` 在同任务显示灵动岛确认；明确拒绝停止任务。无效/缺失审计转人工；目标变化直接返回新观察，不执行旧坐标。

独立外部 Phone Use / AutoGLM 的 Auto 使用额外模型请求审计候选动作及本次截图/树，规划响应中的批准不能批准自身。网络或格式错误转人工，取消、期限耗尽和中断继续停止。原生审计使用小爱当前主模型的额外工具轮，独立循环使用配置的同一模型；两者都不是独立安全模型的保证。

人工确认使用小爱灵动岛「确认本次操作／停止任务」，前后台共用，不切换执行屏幕。批准绑定 UID、任务及一次性 token；拒绝、取消或 60 秒超时停止任务。批准后再次复核目标；系统授权还要求完整前台/树一致，出现、替换或消失均使原批准失效。同任务重新观察规划，不重放旧动作。后台不因授权失败切换到物理屏；显式应用冲突交接仍遵循原任务同意流程。

锁屏、安全窗口、密码输入、验证码/CAPTCHA、任务所有权、取消与超时限制对三档始终生效。设置页独立模型测试没有小爱 UID 的确认观察器，遇人工确认仍 PAUSE 并提示从小爱对话发起。未知 ROM/语言/授权模板及真实模型的自主判断需实机单独验证，不能把 JVM 模拟通过等同设备或真实模型通过。

2026-10-18 已在 xuanyuan／API 37／小爱 8.3.30.4420 完成确定性实机验收：三档设置保存与重建、31 阶段前后台确认、真实 Android chooser 同会话选择均通过。审计回复为测试 fixture，没有请求真实模型；具体证据与未覆盖范围见 [验证记录](validation.md)。
