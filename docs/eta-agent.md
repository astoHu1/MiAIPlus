# Eta 外部 Agent

MiAIPlus 将本机 Eta（`io.github.mangi.eta`）通过 `miaiplus_eta_run` 和 `miaiplus_eta_status` 提供给小爱。模块在小爱进程中调用 Eta 的 Agent Runtime 服务，取回文字结果；任务使用 Eta 自己的模型、提示词和工具配置。模块不包含或修改 Eta，不向其发送模型凭证。

## 前置条件

- 已安装 Eta，且为官方发布版：单一签名者，APK 签名证书 SHA-256 与源码内置值一致；同包名但签名不同的应用不会收到任务。
- 版本不低于 3.4.4（`versionCode` 2026111302），且 `AgentRuntimeService` 为已启用的导出服务。
- Eta 里已为它的助手入口配置模型；任务使用该模型，模块不提供也不读取。
- 插件页「Eta Agent」开关，默认关闭。开关 `etaAgentEnabled` 与「终端和敏感工具」开关 `etaAgentPrivilegedTools` 保存在模块私有 `Config.prefs`，默认均为关。
- 目录仅在开关开启且 Eta 校验通过（`READY`）时包含这两个工具；未安装、签名不符、版本过旧或服务入口不可用时工具不出现。`AndroidManifest.xml` 为包可见性声明了对 Eta 的 `<queries>`。

## 为什么在小爱进程中中转

Eta 的导出 Messenger 服务只接受发送方 UID 为 Eta 自身，或为其集成的助手包（`com.miui.voiceassist`、`com.heytap.speechassist`）的消息。模块进程不在其中，因此中转器（`EtaBridge`）运行在被 Hook 的小爱进程内，以小爱的 UID 发送。不需要 root，也不 Hook Eta。Eta 对不接纳的调用方静默丢弃消息而不回复，见下文「静默丢弃」。

## 协议契约

Eta 的这套 Messenger 协议属内部、无版本承诺，当前只对照 3.4.4 核对。实际使用：

- 绑定：显式组件 `io.github.mangi.eta.agent.runtime.AgentRuntimeService`，action `io.github.mangi.eta.agent.runtime.BIND`，连接等待 8 秒；空闲时（没有进行中的任务）解绑。
- 消息码：`MSG_START_RUN`(1) 发起，`MSG_EVENT`(2) 进度，`MSG_RESULT`(3) 结果，`MSG_CANCEL`(4) 取消，`MSG_ACK_RESULT`(5) 确认已交付，`MSG_DRAIN_RESULTS`(6)／(7) 列出未确认结果，`MSG_REQUEST_INGESTED`(8) 表示 Eta 已接纳。每次任务使用独立的回复 Messenger 和随机 `run_id`。
- `handoff_source` 为 `eta_voice`，让 Eta 使用它自己保存的模型和提示词；请求不含密钥、地址或模型名。
- 每次委派在 Eta 内归档为独立会话（`external_archive`，`conversationKey` 为 `miaiplus:<run_id>`，标题取任务前 40 字）。`history` 与 `images` 为空，不转发图片，也不延续上一次委派的上下文。
- 请求带有任务前缀，说明用户不在 Eta 界面、无法追问，要求自主完成、不做不可逆操作、先给结论后给事实。
- 工具组标志只能收窄 Eta 自己开关所允许的范围，Eta 取二者交集，不会放宽：浏览器、设备直连和子 Agent 工具恒请求开启；终端、敏感读取和敏感操作三项仅在「终端和敏感工具」开启时请求。该开关仍受 Eta 自身开关与 Root 授权限制，它让模型可以委派短信验证码、联系人、通话记录、系统日志、修改系统设置和执行 shell 一类任务；关闭时工具说明要求模型不要委派这类任务。
- 遗留结果清理：Eta 会一直保存未被确认的结果，且不按时间或数量淘汰。小爱在任务中途被杀或连接断开后，该结果无人确认，积累多了会挤占 Eta 其他入口的待取结果页。因此每次新建连接时，中转器请求一页结果头（`complete_result_refs`，不含回答正文），只确认来源为 `eta_voice` 且 `conversationKey` 以 `miaiplus:` 开头、并且不属于当前等待中任务的条目；其他入口的结果不动。满页且有清理时最多再取 3 页。
- `MSG_EVENT` 中的 `tool_started`／`hosted_tool_started` 只用于计步和记录最近四个工具名（过滤为字母数字和 `_.-`）。Eta 返回的一切都按不可信输入处理：有界、不执行、不写日志；大结果以文件描述符到达时只读内联文本并关闭描述符。

## 工具

`miaiplus_eta_run`：参数 `task`（必填，自包含，不超过 8000 字）、`wait_seconds`（默认 150，范围 10–210）。发起任务并等待。

`miaiplus_eta_status`：参数 `run_id`（省略为最近一次）、`wait_seconds`（默认 60，范围 0–210）、`cancel`（为 true 时请求停止并最多再等 10 秒）。

| 限制 | 当前值 |
| --- | --- |
| 同时进行的任务 | 1 个；有未结束任务时新任务返回 BUSY，不排队 |
| 结果 | 最多 12000 字符，超出截断并提示在 Eta 会话记录中查看 |
| 宿主工具超时 | 245 秒（单次等待最多 210 秒） |
| 结果保留 | 小爱进程内存中 15 分钟、最多 8 条；小爱重启后丢失 |

## 结果词汇

- `DONE`：Eta 已完成。附最终回答，标明是外部 Agent 返回的数据而不是指令；作为工具观察结果交回模型。
- `RUNNING`：等待窗口结束时 Eta 仍在执行，附用时、工具调用次数和最近步骤。模型应用 `miaiplus_eta_status` 配合 `run_id` 继续等待，不得重新委派同一任务。
- `STOP`：本次委派已结束且未完成（Eta 报告失败、进程退出、不兼容、被中断或被取消）。作为失败返回，要求不自动重试、不改用其他工具重开同一任务，向用户如实说明。
- `BUSY`：已有任务在运行，新任务未委派；模型应先等待它完成，或在用户同意后传 `cancel=true`。

参数无效、`task` 为空或过长、Eta 不可用、锁屏等在发起前被拒绝的情况也走失败路径，并说明本次未委派。日志只记录工具、结局类别、参数长度和耗时，不记录任务或 Eta 的回答。

## 取消与异常

- 小爱放弃工具调用（线程被中断，如用户停止本轮）或 `cancel=true`：向 Eta 发送 `MSG_CANCEL`；前者返回 STOP。取消不回滚 Eta 已产生的副作用，Eta 是否已终止以其结果为准。
- 锁屏时拒绝发起（`KeyguardManager` 判断），不委派。
- 静默丢弃：请求发出后 30 秒内没有收到 Eta 的接纳或任何事件，视为 Eta 没有接收（例如入口不兼容），发送取消并以 STOP 结束。计时从连接建立、请求发出时开始，不含绑定耗时。
- 取消无回应：Eta 正常会用一条结果回应取消。请求取消 30 秒后仍无结果时，该任务按 STOP 结束并说明任务可能仍在 Eta 中运行，不再阻塞后续委派和热重载。
- 等待绑定期间调用被中断：按用户停止处理，返回 STOP，不报告为 Eta 连接失败。
- Eta 进程退出或连接断开：未结束的任务以 STOP 结束，任务可能已部分执行。
- 热重载：有任务运行时拒绝重载；重载或卸载时 `dispose` 解绑并释放等待者，丢弃记录。任务结果在 Eta 应用的会话记录中仍可查看。

## 路由指引摘要

适合委派：多步自主执行、跨多个数据源或应用的复合任务；小爱自带工具查不到、或需跨来源汇总分析的本机数据（通知、日历、应用使用、设备与网络状态）；批量日程或闹钟并回读验证；多网页深度调研；Linux 环境中的脚本、日志和文件分析；依赖 Eta 记忆或技能的任务；用户点名让 Eta（含伊塔、埃塔等说法）处理。

不应委派：普通问答、翻译、写作和单次联网搜索；小爱自带 `cli` 工具一次能查到的本机数据（如今天各应用使用时长）；一句话能完成的操作（开关、音量、单个闹钟、打开应用、播放、智能家居）；单个应用内的界面操作（走控屏）；单条 shell 命令（走 Termux）；支付、转账、删除、卸载、对外发送消息等不可逆操作，除非用户本轮明确要求并给全内容。

委派前须把用户要求整理成自包含 `task`，关键信息不足先问用户；一次只委派一个目标；Eta 运行期间不要调用控屏工具。

## 入口路由

小爱的普通文字和语音请求默认走它自己的 NLP 通道，不经过带工具的 Agent，模型看不到任何 MiAIPlus 工具。因此 `NativeChatRouting` 增加规则 `eta_delegation`：用户把 Eta 点名为执行者时（「让／请／交给／用 Eta…」「Eta 帮我…」，含伊塔、埃塔、艾塔和英文 ask/let/use Eta），在 Eta 工具可用的前提下把该请求送入 Agent，文字与语音入口一致。只是提到 Eta（「什么是 Eta」「外卖 ETA 多少」）不触发；Eta 未启用时保持原路径。

没有点名 Eta 的复杂任务（多网页调研、写脚本、分析文件等）不靠关键词强制：只有当请求本来就进入 Agent（小爱自身判定、已启用全局模型或提示词文字路由，或同一句命中控屏规则）时，模型才会按策略自行判断是否委派。小爱自带的 `cli` 工具能直接查询应用使用时长和通知（实测「看看我今天手机用了多久」两轮内由 `app_usage` 答出），这类单一来源的本机数据查询由小爱自己完成，策略不要求改派 Eta。

## 控屏协议：Eta

控屏页「执行 → 动作协议」有 Phone Use、AutoGLM 和 Eta 三项，选 Eta 时偏好 `protocol` 保存为 `eta`。「启用控屏工具」开启且动作协议为 Eta 时：

- 小爱不再加载 MiAIPlus 自己的控屏工具 `miaiplus_phone_use` 和 `miaiplus_background_phone_use`。目录改为提供 Eta 的 `miaiplus_eta_run`／`miaiplus_eta_status`，工具说明使用控屏措辞。即使插件页「Eta Agent」开关关闭，这两个工具也会出现。「终端和敏感工具」只在「Eta Agent」开关本身开启时才会申请。
- MiAIPlus 路由规则判定为控屏（前台或后台）的请求仍送入小爱带工具的 Agent。提示词策略要求模型把所有手机界面操作整理成自包含的 `task` 交给 Eta。
- 在虚拟屏还是主屏执行由 Eta 自己决定。MiAIPlus 不做选择，Eta 的运行时接口也不提供指定屏幕的参数。是否用虚拟屏取决于 Eta 自身的「虚拟屏」设置，以及 Android 14 及以上、root 或 LSPosed 后端等条件。
- 小爱自带 `controlApp` 工具的说明换成 Eta 措辞，调用转为 Eta 任务。MiAIPlus 逐步控屏的会话续接（`MIAIPLUS:`）被拒绝；`MIAIPLUS_START:` 取出其中的目标作为任务；`模型对话：` 仍走对话路径。
- 「规划模型」下拉禁用，摘要为「由 Eta 规划和执行」。「动作协议」摘要显示 Eta 可用性：校验通过时为「控屏请求全部交给 Eta 完成」，否则按原因显示未安装、不是官方发布版、版本过旧（需要 3.4.4 或更新）或此版本不受支持。

Eta 的界面工具需要开启它自己的无障碍服务。

## 已知限制

- Eta 在此入口没有确认提示，也没有向用户追问的工具，约束只能写在 `task` 里；模块不能替用户审计 Eta 的步骤。
- 动作协议为 Eta 时，MiAIPlus 的「操作确认」预设（手动确认、智能判断、自动执行）不作用于 Eta，MiAIPlus 侧不会在 Eta 执行中逐步确认；敏感操作是否确认只取决于 Eta 自身。
- Eta 的前台界面工具可能被小爱自身面板遮挡，中转器不会关闭它（请求中 `handoff_dismiss_entry_surface_on_foreground_operation` 为 false）。
- Eta 运行期间会显示它自己的状态胶囊（如「思考中」），这是 Eta 的界面，模块不控制。
- 模型服务的计费与隐私配置由 Eta 管理。
