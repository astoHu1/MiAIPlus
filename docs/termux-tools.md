# Termux 工具执行契约

2026-11-11 根据手机端双工具实测反馈修订。反馈中的命令替换消失及 `/home` 错误路径，在本轮直接调用仍运行的旧服务时未重现，不能据此认定根因已复现；源码确认的 lint 改写、dash、分流拼接、摘要冗余和固定短时限分别修复。此文描述工作树实现；设备与构建证据见 [本轮记录](validation/termux-ux-2026-11-11.md)，不等同于 GitHub Release 已分发。

## Shell 与输出

内置 `miaiplus_termux_run` 和 `miaiplus_termux_run_digest` 使用 Termux 的 **Bash**，每次独立运行。`cmd` 原样交给 `bash --noprofile --norc -c`：不经 shell lint 重建，不预先展开变量，不插入 `-y`、不移除 `sudo`，不改写 `cd`。命令替换、算术、反引号、引号、重定向、数组与管道均由 Bash 解析。嵌套调用 `sh -c` 仍使用该 `sh` 自己的语法。

默认 cwd 为服务私有 HOME；`cwd` 可指定已有绝对目录。`HOME` 和 `TMPDIR` 都是实际创建的目录，结果中的 `home_dir`、`tmp_dir`、`cwd` 和 `shell` 可供核对。HOME 隔离只隔离状态，不限制 Termux UID 的访问能力；不会把模型命令提升为模块 root。

先用 Bash `-n` 检查语法。语法失败返回 `E_SYNTAX` 和 `executed:false`，整条命令不执行。`cmd` 回显保留原字符串，包括首尾空白；策略拒绝也不改写后执行。没有 tty，stdin 为 EOF；安装软件时应由调用者明确选择包管理器的非交互参数。

stdout 和 stderr 在创建子进程时合并，按到达同一管道的写入顺序保留，`2>/dev/null` 等重定向由 shell 正常执行。不同进程自身的缓冲仍可能影响写入顺序。短输出仅在 `out` 中返回，不生成 `summary`、`facts` 或猜测错误根因；非零退出保留实际退出码并返回 `E_EXIT`。MCP 的文本与结构化结果在 JSON 内容等价时只向模型呈现一次，不依赖键顺序或斜杠转义一致。

输出超过 12000 字符时，`out` 为首尾摘录，`truncated:true`，完整文本由 `out_ref` 配合 `miaiplus_termux_out_read` 补读。单命令最多保留 4 MiB 输出，超出停止进程组并返回 `E_OUTPUT_LIMIT`，避免持续输出耗尽存储。

## 超时与后台任务

同步调用默认 `timeout_ms:10000`，可配置为 100–40000 毫秒。模块 HTTP 总预算仍是 60 秒；托管服务 SSE 每 15 秒保活，托管客户端读取等待为 20 秒。排队、启动和网络仍消耗模块原有预算，不保证任意冷启动加最长命令都能在一轮内完成。

超过同步预算的任务使用原生后台接口，不需要 shell `&` 或 `nohup`：

```json
{"cmd":"git clone https://example.com/project.git","background":true,"timeout_ms":120000}
```

立即返回 `job_id` 和 `running:true`。使用 `miaiplus_termux_job_status` 传 `{"job_id":"..."}` 获取当前输出和运行状态；完成后返回实际退出码、错误及可能的 `out_ref`。适当间隔轮询，不要重复提交原命令。`miaiplus_termux_job_cancel` 请求取消该任务及其同进程组的子进程；继续查到 `running:false` 才算退出，既有副作用不回滚。主动创建新 session／进程组的程序可能脱离该组，不把它称为任意后台服务管理器。

后台默认及最大时限均为 120 秒。服务最多同时执行 4 条命令，包括同步和后台；超额返回 `E_BUSY` 且未执行。任务记录最多 16 个，完成 30 分钟后或容量回收时失效；服务重启不保留任务。运行中的后台任务占用槽位，完成记录先回收。小爱原生停止按钮、插件停用和模块热重载不等同于取消已提交的后台任务，应显式使用 `job_cancel`。

策略仍由上游 gate 检查，模型不能提供 `confirmed`，后台接口也不能越过 `E_CONFIRM`／策略拒绝。首次请求和执行前均复查。取消或 HTTP 中断不保证远端尚未执行，不能自动重试有副作用的命令。

## 旧服务升级

旧三工具配置可以读取保留。更新 APK 后在「插件 → Termux 配置」点击「重新配置」，才部署新适配器及五工具目录。旧服务不具备新版就绪证明，因此不能被误认为已经修复。

从旧三工具配置升级会生成新的回环端口和凭证，并保留旧服务、文件与配置目录，不强行终止可能仍在运行的命令。旧私有 HOME 不自动搬入新 HOME；需要的文件仍可通过明确路径访问。新服务的按需启动复用已经部署的版本。不要把 APK 覆盖安装本身当作 Termux Python 服务已更新。

## 与小爱本地 CLI 的分工

小爱的 `cli` 是宿主闭源工具，本仓库没有 `find`、`grep`、`ls`、`help` 的实现。此次没有声称给它新增 `find --json`、递归默认值、路径提权或帮助子命令，也不绕过它的路径限制。

- 系统应用、日历、便签、通知与设置操作使用宿主 CLI。
- CLI 文件匹配明确使用 `grep -r`；文件元数据可用其现有 `find -printf`，不要假设已有 `--json`。
- 原始 shell、root、Python、git、网络请求和长任务使用 Termux。需要结构化文件元数据时可运行 Python，以 `os.stat` 和 `json.dumps` 构造真实结果；文件名可能带空白或换行，避免按空格切分 `ls -l`。
- 路径不可访问是实际权限边界。Termux 也没有默认 root；只有用户任务确实需要且系统授权允许时，才显式运行 `su -c`。

本轮不自动修改软件源，不用报告中的安装／镜像建议作为设备操作指令。镜像选择、网络速度和包管理副作用应与 shell 正确性分别验证。
