# 小爱会话调用 Termux MCP（2026-11-06）

在 API 37 设备上使用已有的 MiAIPlus 主线 `1.0.2-preview` 和小爱 `8.3.30.4420`。小爱负责会话和工具编排，推理由设备原先配置的全局接管模型完成。测试从小爱全屏的新话题发送，模型自行发起工具调用；没有 mock、固定代理探针或模型代答。

沿用上游 [termuxgpt/termux-mcp](https://github.com/termuxgpt/termux-mcp) `0.15.0`，固定 commit `48e3e58b3c8c5d66b97e79c0fa6473d126508f46`，不改上游执行实现。用 Termux 普通应用 UID 启动，监听手机 `127.0.0.1:18871/mcp`，启用 Bearer 认证和 10 秒 shell 超时。无 Token 或伪造 capability Token 均返回 401。MiAIPlus 插件页显式选择 `2025-06-18`，发现并启用 `run`、`run_digest`、`out_read`。ADB root 用于准备隔离目录和核对设备状态，没有给 shell 提权；隔离 HOME 只分离服务状态，不是额外的文件访问沙箱。

| 用例 | 调用与实测结果 |
| --- | --- |
| 读文件与核对执行身份 | 1 次 `run`。回复准确给出文件中的随机标记和 Termux 普通 UID；提示词没有给出这些值。 |
| 读取指令、生成并校验报表 | 第一次在读到说明后尝试 `cd "$HOME/bench"`，上游把路径当成字面量，返回目录不存在；该轮停止。提示模型直接使用文件路径后，5 次 `run_digest` 完成读说明、检查 CSV、生成 TSV 和独立回读校验。实际文件字节与预期一致，汇总为 bamboo 38、azuki 35、nori 35，回复中的 SHA-256 与主机对设备文件独立计算的结果一致。 |
| 真实非零退出 | `run_digest` 上游响应含 `isError=true`、退出码 `7` 和 stderr 探针标记；小爱显示「插件工具执行失败或已停止，本次调用未重试」，没有发出已要求的后备读取。 |
| 退出码作为普通结果的对照 | 外层 shell 捕获子进程的 `7`、输出 `child_exit=7` 后正常退出。模型观察到该结果，第二次调用读出后备文件的随机标记，两个值均正确。 |
| 大输出引用接力 | `run_digest` 读取 49,827 字节、601 行的测试文件，返回 `out_ref`。模型用第二次调用 `out_read(ref, tail=1)` 取回最后一行，随机标记与实际文件一致。 |

这组样本说明成功的工具结果可驱动下一步，即使下一步使用另一工具；当前实测的普通 MCP 错误却无法驱动同轮恢复。报表重试给出了路径提示，大输出测试也明确要求使用引用，两项都不能据此推断模型在开放任务中会自行选择这些策略。没有测试小米官方模型、语音入口、控屏混合任务、取消、持久终端或长时间任务。

设备保留已启用的插件和 Termux 服务，以及隔离目录中的合成测试文件。测试审计已关闭，临时 ADB 转发已移除；没有替换 APK、改变模型配置或加入开机自启。服务若被系统回收，可在 Termux 中重新运行部署目录下的 `start.sh`。本轮仓库只补充文档，未运行构建或 Lint。
