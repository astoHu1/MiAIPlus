# Termux Agent 可用性修复与验收（2026-11-11）

针对手机 Agent 提供的双工具报告检查源码与真实设备。报告是故障线索，不把其中安装软件、改源、放宽路径／确认的建议当作设备操作授权。此次只部署受管服务修复和验收命令，没有安装／卸载 Termux 软件包、修改镜像或放宽确认策略。

## 结果与边界

- 受管 `run`／`run_digest` 直接以 Bash 执行原始 `cmd`，不经 lint／preprocess 改写；返回真实 HOME、TMPDIR、cwd。语法失败在执行前明确拒绝。
- stdout/stderr 在进程创建时合并；短输出去掉自动 summary/facts；JSON 结构等价时去重，兼容不同键顺序和 `/` 转义。
- 同步超时可配至 40 秒；原生后台模式最长 120 秒，配套状态与取消工具。四执行槽位、十六任务记录、输出 4 MiB 上限、进程组清理与所有权检查均有回归。
- 旧三工具配置可加载。重新配置以新回环端口部署新版并保存五工具目录；保留旧进程和私有文件，不终止可能属于原任务的命令。详细升级、取消和结果保留边界见 [执行契约](../termux-tools.md)。
- 小爱原生 CLI 不在此仓库内；没有新增其 `find --json`、`help --brief` 或放宽路径权限。工具说明及文档说明 `grep -r`、`find -printf` 和 Termux 的适用范围。

**原始 P0 的复现限制：**从桌面通过临时 ADB forward 直接调用设备上原有的旧服务，`printf 'line%d\n' $(seq 1 2000) | wc -l` 返回 2000；单引号 `$HOME` 保留字面值，算术返回 7，`2>/dev/null` 也正常。未重现报告中的替换整体丢失和 `/home` 错误展开，不能认定已经找到这两项原始故障的完整根因。源码能确认 lint 存在其他自动改写、默认 dash、stdout/stderr 分别捕获后拼接、摘要以及固定短时限问题；本轮修复并为报告中的语义增加回归，保护当前链路。

604 项 JVM／Robolectric 测试通过。Debug／Release 完整 Lint 零错误、零 Fatal（分别 38／27 个 Warning）；四种 APK 构建完成。Python 的 12 项行为回归使用实际 APK 内的固定上游与适配器源码，覆盖命令原文、引号／替换、Bash 数组、cwd 隔离、输出顺序、语法不执行、超时、后台取消与子进程退出、大输出补读、策略拒绝、并发槽位与任务所有权。Python 编译、启动脚本语法、资产可重建及 `git diff --check` 通过。

首次本地回归修正了 macOS `/var` 软链接、BSD `ls` 退出码差异，以及空进程组在 Darwin 返回 EPERM 的清理行为；新增输出管道读取上限，避免先无限写临时文件再截断。初版测试对旧工具描述的断言及 readiness fixture 一度失败，修订后全部通过，未将失败轮计为通过。

## 真实设备

ADB 无线连接 Xiaomi 15 Ultra（API 37）、小爱 `8.3.30.4420`、Termux `0.118.3`。使用已有 root 和 Python；覆盖安装同签名 Debug，由新增 `termux_managed` runner 调用 **真实 PluginRuntime → McpClient → Termux HTTP 服务**。没有用 mock 替换 shell。

| 检查 | 观察 |
| --- | --- |
| 重新配置 | APK 内实际资产自动部署；服务以真实 Termux UID 运行；发现并保存 run/run_digest/out_read/job_status/job_cancel 五工具 |
| 原文与语义 | 含首尾空白的 cmd 回显完全相同；`$()`、反引号、算术、单引号 `$HOME` 和 2000 行替换计数均正确 |
| 环境与 shell | HOME/TMPDIR 是存在的真实目录；Bash `[[ ]]`、中文数组均成功 |
| 重定向与输出 | `2>/dev/null` 无泄漏；交错 stdout/stderr 为 `abc`；短输出无 summary/facts；结果可严格解析为单个 JSON 对象 |
| 语法 | `printf SHOULD_NOT_RUN; if then` 返回 E_SYNTAX、executed:false，没有执行前缀 |
| 静默同步 | `sleep 16; printf QUIET_OK` 在 20 秒配置下通过 SSE 和模块桥接成功，跨过旧 10 秒限制和一次 15 秒保活 |

| 宿主代理 | Debug 的 DUMP 保护固定命令探针通过小爱实际 ToolRegistry 和当前模块代理执行，核对 cmd 原文、算术、替换与字面引号；无图片／控屏任务，探针报告恢复 |

第一次设备运行全部功能检查通过，但结尾把自动热重载更新的 `hook_status` 当成用户配置变化而失败。修订检查只排除诊断字段后，完整 runner 以 `INSTRUMENTATION_CODE: -1` 结束并明确 PASS。没有把此轮确定性探针当作真实模型自主选择、包下载安装速度或任意任务成功率验收；未测小米官方模型、空白 Termux 或其他 ROM。

最后覆盖安装优化 Preview，逐项比较非诊断偏好未改变；五工具目录与新版 HMAC 就绪证明核验通过，未在锁屏后执行 shell 任务。移除本轮临时 ADB forward。保留升级后的服务和插件目录、旧服务与文件，原模型与其他用户配置保持。最后发送 KEYCODE_SLEEP 并读取系统电源与窗口策略，确认锁屏显示、输入受限及主显示不再处于正常点亮界面。
