# 前台语音入口与截图归属（2026-11-08）

本轮处理“在微信全屏查看抖音截图，要求小爱去抖音打开原视频，首次只给步骤，追问控屏后把截图当成原视频”的反馈。起点为 `8c67ea7`，测试设备为 Xiaomi／API 37、小爱 `8.3.30.4420`。本页区分源码确认、合成场景、真实模型和真实应用证据；不把计算器测试算作微信／抖音原任务成功。

## 调查与修正

- 前一轮只为明确后台请求补选工具 Agent。文字入口在 `globalModel=true` 时已经选择 MiClaw，但最终语音识别入口没有这个同等保证；前台语音操作仍可能走 AIVS NLP，绕过模块工具与策略。现在明确的应用内操作和“用控屏自己操作”等承接请求也检查对应插件后进入原生工具入口。普通聊天、教程、否定请求和仅打开应用保留原有路径；请求归属、取消和重复 Final 防护继续生效。
- 进入 OSBot 后，每轮模型请求都会注入当前工具定义，没有找到“必须等第二轮才加入控屏工具”的静态逻辑。实机初次修复尝试中，首轮元数据已确认前台工具、扩展策略及完成规则可见，但模型回答“没有图片附件，请重发”，没有读取当前屏幕。因此进一步说明：明确的应用操作请求中，“这张图／这个视频”可以指手机当前画面；首次提交 `goal` 会取得观察，不应仅因聊天无附件而要求上传。普通识图问题不据此授权操作。
- 旧观察包含前台包名，但完成主要依赖模型看图判断。现在观察开头明确系统窗口包名、执行屏幕和 displayId，并说明截图里的应用外观不能覆盖真实宿主身份。找原内容还须核对作者、标题与实际页面状态。
- 根据用户后续反馈，撤回初版 `finish(app,message)` 完成门槛：不强制声明或匹配目标包名，不强制非空说明，不为 finish 额外观察或消耗拒绝预算。原生、独立 phone_use 和 AutoGLM 均恢复由模型基于完整目标与最新观察判断完成；系统前台信息及截图归属提示保留。
- 实机终态回归暴露了 Provider 提前插件检查把过期会话原因泛化的问题。会话验证与插件读取现分开处理，保留“会话不存在或已过期”的具体原因，不创建新任务或改变已完成任务身份。

包名信息用于让模型辨别当前所处应用。模型自己声明的目标包名与系统包名相同，也不能证明原视频身份或业务目标完成，因此不作为统一完成门槛。原有任务归属、权限审计、动作确认、锁屏等执行限制继续生效。

## 设备方法与阶段结果

`--native-foreground-model` 使用真实文字发送；`--native-foreground-voice` 启动真实 main ASR 请求并提供合成最终识别文本，要求单次 MiClaw 提交及重复 Final 抑制。后者不验证声学识别、热词或实体按键。默认保留用户模型；加 `--official` 临时关闭全局替换，结束后逐项恢复配置。

固定计算器用例从自有全屏图片查看器开始：像素显示 `137×29=3973`，无障碍只有图片描述，实际包名为模块。自然请求要求去计算器打开图中算式、清屏重算；没有附图，也没有在请求中命令使用某个工具。通过条件包括首张观察确为图片宿主、单一前台会话、真实计算器操作、最后 owned 帧的当前公式和结果经 OCR 核验、实际 finish、清理及配置恢复。历史栏中的正确结果不能代替当前计算区。

阶段记录：

- `configured-voice-1.log`：首轮策略和工具可见，但模型要求重发图片，未调用控屏。主机主动取消并清理，不计通过；本轮据此补充当前屏幕无需附件的说明。
- `configured-voice-2.log`：已启动前台工具，从图片查看器真实 launch 计算器；ADB 随后断开，主机流程中断，不计完整通过。重连后核对配置与原始快照一致。
- `terminal-1.log`：在原有过期续调断言处失败，原因是 Provider 提前检查抹掉具体原因；不是完成校验通过的证据。修正后需以新的完整回归结果为准。

第一次计算器人工复核发现，前台科学计算器的结果文字底部位于图片高度约 40.2%，旧脚本只接受 24%–40%。脚本新增显式 `--foreground`，前台改为 24%–42%，后台默认区域不变；历史仍在 24% 以上、键盘在 43% 以下。用实际正确结果帧复核为通过，用“历史有 3973、当前只有 13”的实际帧复核为拒绝，随后官方语音项获得完整自动通过。没有用全图数字搜索或旧帧证明替代当前结果。

视频项使用从手机真实抖音公开 feed 取得的截图，放入模块固定私有 cache 供自有全屏图片查看器显示；启动测试前已让抖音离开原视频。没有向微信联系人发送消息，没有使用用户私聊图片，也没有用固定模型回答。初始真实包名为 `io.github.miaiplus`，进入后的真实包名为 `com.ss.android.ugc.aweme`。人工核对导出的目标应用图片确认模型实际按截图线索进入搜索、多次修改查询，最后未确认原视频而调用接管。程序的 PASS 只验证这条工具行为链，不验证原视频身份；未复现微信图片查看器本身。

修订前这些记录的首轮元数据确认扩展策略、前台工具、系统前台规则与当时的 finish app 契约可见；当前已撤回该契约。早期日志的 `modelMode=configured` 是探针固定文字，官方项应按 Runner 的临时 `globalModel=false` 配置和 `mimo-omni` 元数据判断；新探针已直接记录实际 `globalModel`。探针会在工具终态后清理 owned turn，诊断聊天截图可能显示宿主通用服务错误，不能用于证明最终自然语言回复准确或接管原因已完整呈现。
