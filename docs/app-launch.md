# 控屏应用启动

## 启动路径

需要识屏、点击或输入的任务先进入控屏会话，再调用 `launch`；单纯打开应用仍走小爱原路由。控屏启动由模块无障碍执行器统一解析、提交并确认前台结果。

首次观察提供本机可见的可启动应用列表，模型使用包名。解析只接受启用且可导出的 MAIN/LAUNCHER 入口，不接收任意 Intent 或组件。一个包的多个 launcher 不再误判为名称歧义；不同包同名时要求包名。启动保留既有任务；目标已在前台时不重复提交启动。

当前源码的前台启动优先使用独立、一次性的 root helper。模块先完成上述目标解析，再让 helper 在同一 Android 用户下执行固定形态的 `am start --display 0`，仅提交已解析的 launcher 组件。此路径用于避开 ROM 对模块身份跨应用启动的拦截，不修改授权数据库、AppOps 或全局策略。helper 的启动与 READY 握手有短期限，等待可取消并检查锁屏；当前任务通过独占连接控制请求，连接 EOF、取消或超时会终止等待并回收 helper。提交前再次检查取消、锁屏和请求期限；已经交给 Android 的启动不能撤回，检查与提交之间仍有极短的竞态窗口。

只有请求发送前确认 root 路径不可用或失败时，才回退为模块身份的标准显式 `startActivity()`。请求一旦开始发送，响应丢失、启动失败或等待超时都不再换路径重试。该前台 helper 独立于后台虚拟屏 helper；后台任务的屏幕归属、确认与故障停止规则继续有效，不以此路径回退物理屏。

## 自动处理小米启动确认

执行器只在当前 `launch` 等待期间自动处理小米安全中心的“本次允许”，并核对：

- 窗口所属包为 `com.miui.securitycenter`；
- 固定资源 `permission_group_title` 为“启动应用”或“打开应用”，`event_title` 的完整请求文案与模块发起方和本步目标包名/应用名称一致；
- 存在唯一、可见、启用且可点击的“本次允许”按钮，并有拒绝/取消选项。

每个动作最多点击一次“本次允许”，不选择“始终允许”，不修改系统授权数据库或全局策略。匹配的遗留同目标确认也可直接完成，不再提交第二次启动。其他应用伪造的文字、不同发起方/目标、相机/通讯录/安装等权限不会匹配。ROM 修改控件 ID、语言或文案后可能需要重新适配。

## 真实结果确认

启动后每 250 毫秒检查焦点窗口，要求目标包稳定前台至少 500 毫秒，通常最多等待 10 秒。若匹配的启动确认在期限末尾才出现，自动点击后保留一次 1.5 秒的过渡宽限，让确认窗口退出并完成目标稳定检查；已点过的确认持续可见达 1.5 秒时，返回当前观察。自动点过允许也不等于启动成功；未真正打开、短暂闪现后退出或跳到其他应用，都不能报告已打开，不循环重试。任务取消和锁屏立即停止。

出现可读的系统应用选择器、未匹配的启动确认或其他系统授权时，`launch` 返回待选择/确认的观察，同一任务继续，由模型规划下一步；这不等于目标已经进入前台。启动后新出现的未知或无标题安全中心窗口也返回观察，避免 ROM 模板变化导致会话直接超时。若最初就是普通安全中心页且始终没有变化，等待 10 秒后同样返回该页观察；仅凭相同包名无法区分旧普通页与未识别的确认。普通桌面等其他页面上没有系统提示、也无法确认目标的纯启动超时仍 PAUSE。匹配当前发起方和目标的“本次允许”仍最多自动点击一次。

后台 helper 的正式启动等待也接受本显示上的已知系统授权/应用选择窗口，以 `awaiting_confirmation` 回复，由模块返回新观察；不会因目标暂未占焦点而提前报启动失败。启动前后均检查目标应用的跨屏可见任务，发现主屏或其他屏的目标任务仍拒绝/停止；不在物理屏处理该确认。能力探针继续只把真实目标进入后台屏记为启动能力通过，待确认不是探针成功。

安全中心也有普通首页、清理和电池页面，不能仅凭其包名判定为授权。其可见 `permission_group_title` 将页面区分为启动/打开应用、其他授权和普通页面。普通页面和应用选择由模型操作，其他授权进入本会话 Manual / Auto / YOLO 的审批流程；安装、设备管理、无障碍、未知来源和关闭保护等严重授权保留人工确认。后台屏同样可读取和处理这些窗口，不再仅凭安全中心包名终止，也不会切到物理屏处理。

批准只绑定本步观察中的授权窗口。真正派发手势/输入前再次读取同一屏的前台与树；审批期间出现新授权或文案变化时，作废本步执行并返回新观察重新规划与审批。应用选择器不因此获得敏感系统权限的通行证；密码、安全窗口、锁屏等既有边界保留。后台树优先读取该显示上的焦点窗口，避免将底层目标应用的树当作当前弹窗。

系统弹窗分类仍受 ROM 模板和可读无障碍树限制：小米授权分类使用 `permission_group_title`，其他授权使用已知系统包；未知模板还会按“允许／同意／授权”等目标标签触发审批，未被识别的模板仍需模型正确标注敏感动作。未知模板和语言未实机验收。

原生逐步会话的启动、主页、返回、等待不在执行前重复截图；这些动作不依赖旧坐标，执行后仍会截图。独立外部循环保留执行前观察与批准复核。坐标动作和输入仍保留执行前重观察校验。这样也避免快速连续工具调用触发系统的截图间隔错误。

物理屏截图在每次请求前保留至少 350 毫秒的单调时钟间隔，等待可取消且不复用旧图。截图 Frame 分别携带原始屏幕尺寸和实际压缩 JPEG 尺寸，`image_pixels` 按压缩图坐标换算，避免高分辨率手机点击偏移。

此外，`onInterrupt()` 的无障碍反馈中断不再被当作掉权限；旧服务实例退出也不会取消新实例的任务。真正的解绑/连接失效仍停止执行。
