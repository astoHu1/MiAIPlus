## 结论先行

值得优化，但优先方向是**让每一步拥有简短、自包含的最新状态，并把长轨迹中的必要事实保留下来**，而不是简单增大轮数或把历史全部删掉。

- **两条循环必须分开。** 独立外部 `AgentEngine` 已经只留最新截图和有限历史；默认原生循环的消息／图片历史由小爱宿主管理。不能把“原生每步附图”直接推断为“线上每轮一定上传全部旧图”。
- **原生每步已有目标，但没有结构化进度账本。** `NativeSession` 重发目标、预算、规则和长树；普通动作缺少清楚的 `executed / skipped / waiting_review` 结果字段。目标还在不等于模型能记住早期事实、已做项和失败原因。
- **先做确定性的状态与观察整理，再考虑模型摘要。** 最新状态卡、明确截断的模型树、保留用户约束和最近失败，比先加一个 manager／反思模型更容易隔离收益与风险。
- **短上下文不必然更好。** 早期查到的信息、跨应用包名和未完成约束会被短窗口丢掉；只传树差分或只删安全说明，也可能使弱模型表现更差。
- **输入负担与模型能力分开验证。** 需区分窗口溢出、有效长程记忆弱、视觉定位差、工具协议不熟、页面动态变化及输出推理预算不足；目前没有足够证据把用户观察归因于某一个根因。

以上源码依据见[当前状态](current-state.md)，开源机制及固定版本见[外部参考](upstream.md)，具体设计与边界见[候选方案](design.md)。全部收益均待测。

## 建议后续实施顺序

| 顺序 | 编号／切口 | 第一次实验的边界 | 进入下一步前要证明什么 |
| --- | --- | --- | --- |
| 0 | C0 请求负担分解 | 纯元数据；区分原生官方、原生外部替换、独立外部；不记录正文 | 知道负担来自旧图、长树、规则、schema 还是 opaque output；缺 usage 明示缺失 |
| 1 | C1 最新状态与动作结果 | 保留机器协议外壳，明确实际执行／跳过／等待审计、目标、屏幕、坐标、预算 | 状态不把“已点击”升级成“业务已完成”；附图／续调／停止门仍正确 |
| 2 | C2 模型观察序列化 | 完整行截断、缺失提示、精简节点；内部完整 Frame 不变 | 模型可读负担下降，安全判据仍使用同一原始证据 |
| 3 | C3 有界历史与任务事实 | 先在拥有完整消息数组的独立外部循环实验，按闭合调用组保留 | 早期约束／事实不丢，Responses 配对与 opaque 回放不坏 |
| 4 | C4 原生旧图在线副本策略 | 仅在最终请求证明确有旧 Phone Use 图重复发送后研究 | 可可靠识别来源，用户其他图片与宿主持久历史不被误删 |
| 5 | C5／C6 按需详情、摘要与多角色 | 分别做独立消融，不作为第一补丁 | 整任务成功率／总成本／延迟值得新增调用和复杂度 |

这不是收益排行榜。先测 C0；C1 与 C2 各做一个可回滚实验。不得把所有候选打包后只看总耗时。
